# Справочник по MONOSCRIPT

[English version](language.en.md)

MONOSCRIPT — статически типизированный язык с выводом типов. Он компилируется через LLVM. Программу можно сразу запустить через JIT или собрать в исполняемый файл.

Справочник описывает язык из ветки `dev` [компилятора](https://github.com/MONOPTICAL/MONOSCRIPT/tree/dev). Примеры взяты из его тестов (`tests/frontend`). В комментарии `// →` написано, что программа печатает. `// ошибка:` — начало сообщения компилятора.

## Запуск

| Команда | Что делает |
|---|---|
| `ms file.ms` | Только проверка: лексер, парсер, семантика |
| `ms run file.ms` | Запуск через JIT, код выхода программы — то, что вернул `main` |
| `ms --compile out file.ms` | Сборка исполняемого файла `out` |
| `ms run file.ms --timings` | Сколько времени заняла каждая стадия |
| `ms run file.ms --offOptimization` | Запуск без оптимизаций LLVM |
| `ms --tokens file.ms`, `--ast`, `--semantic` | Показать токены, AST, результат семантического анализа |
| `ms --run_tests [FILTER]` | Тесты компилятора |

В плагине эти действия доступны командами `MONOSCRIPT: Run File` (`Ctrl+F5`), `Compile to Executable`, `Check File`, `Show Tokens`, `Show AST`, `Show Semantic Analysis`.

## Структура программы

### Блоки

Вместо фигурных скобок у блоков вертикальная черта `|`. Тело функции, ветки `if` и циклов начинаются со следующей строки и сдвинуты на одну `|` глубже:

```ms
[i32]main()
|   for i in range(10)
|   |   if i % 2 == 0
|   |   |   echo("even: " + i)
|   return 0
```

Пустая строка внутри блока может состоять из одной `|`. Плагин сам ставит `|` при нажатии `Enter` и убирает целый уровень по `Backspace`.

### Комментарии

```ms
// до конца строки
/* блочный,
   может занимать несколько строк */
```

### Точка входа

Программа начинается с `main`. Она может возвращать `i32` (это код выхода) или `void`:

```ms
[void]main()
|   echo("x")                // → x
```

Другую функцию можно сделать точкой входа меткой `@entry`. Параметров у точки входа пока быть не может:

```ms
[i32]foo() @entry
|   echo("in foo")
|   return 3                 // код выхода 3
```

Если нет ни `main`, ни `@entry`, запуск завершится ошибкой `entry function not found`.

### Глобальные переменные

Переменные можно объявлять вне функций. Они инициализируются при запуске, до `main`. Инициализатор может вызывать функции:

```ms
[i32]f()
|   return 7

i32 g = f()

[void]inc()
|   g = g + 1

[i32]main()
|   inc()
|   echo(cstr(g))            // → 8
|   return 0
```

## Типы

| Тип | Описание |
|---|---|
| `i1` | Логический: `true` / `false` (то же, что `1` / `0`) |
| `i8`, `i16`, `i32`, `i64` | Целые со знаком |
| `float` | Дробное, 32 бита |
| `f64` | Дробное, 64 бита. Тип дробных литералов по умолчанию |
| `char` | Один байт: `'a'`, `'\n'` |
| `string` | Неизменяемая строка, байты в UTF-8 |
| `void` | Отсутствие значения |
| `array<T>` | Массив |
| `map<K, V>` | Словарь, порядок вставки сохраняется |
| `result<T>` | Значение или ошибка |
| `func` | Параметр-функция: `func: f(i32: x) -> i1` |
| Имя структуры | Пользовательский тип: `User`, `Finding` |

**Числа копируются, объекты — нет.** Массивы, `map` и структуры живут в куче под сборщиком мусора и передаются по ссылке. Ссылка на объект никогда не бывает `null`. Отдельную поверхностную копию даёт `copy(x)`.

## Переменные и константы

| Запись | Смысл |
|---|---|
| `i32 count = 0` | Явный тип |
| `name ^= "value"` | Тип выводится из значения |
| `i32 x` | Без значения: числа получают `0`, строка — `""`, `i1` — `false` |
| `const i32 limit = 10` | Константа с явным типом |
| `final limit ^= 10` | Константа с выводимым типом |
| `final i32 limit = 10` | То же, с явным типом |
| `final i32 limit` | Константа, значение присваивается позже |

Без значения можно объявить только скалярную переменную. Массив, `map`, структура и `result` требуют значения:

```ms
i32 x                        // ок, x == 0
array<i32> a                 // ошибка: ... must have a value
array<i32> b = null          // ошибка
```

### Вывод типа литералов

Целый литерал получает самый узкий тип, в который он помещается: `0` и `1` — `i1`, до `127` — `i8`, до `32767` — `i16`, дальше `i32` и `i64`. Поэтому переменная, выведенная из маленького числа, тоже получается узкой:

```ms
x ^= 1
x = 2                        // ошибка: ... does not fit
y ^= -5                      // i8
y = 100                      // ок
```

Если нужна переменная побольше, укажите тип явно: `i32 count = 0`.

Дробный литерал всегда `f64`:

```ms
v ^= 0.1
echo(cstr(v + 0.2))          // → 0.30000000000000004
```

Пустой литерал `[]` или `{}` без типа вывести нельзя: `x ^= []` — ошибка. Пишите `array<i32> x = []`.

### `final` с присваиванием позже

Значение нужно присвоить ровно один раз на каждом пути выполнения до первого чтения:

```ms
i32 n = 0
final i32 x
if n > 0
|   x = 1
else
|   x = 2
echo(cstr(x))                // → 2
```

Ошибки компилятора:
- присвоено дважды — `Final variable 'x' is already assigned`;
- прочитано раньше присваивания — `Final variable 'x' is used before it is assigned`;
- присвоено в цикле — `cannot be assigned in a loop`.

### Константные объекты

`const` запрещает и переприсваивание, и изменение содержимого:

```ms
const array<i32> a = [1]
a[0] = 2                     // ошибка: constant
```

### Области видимости

Переменная, объявленная внутри `if`, `while` или `for`, видна только в этом блоке. После него имя можно объявить заново:

```ms
i32 n = 1
if n == 1
|   i32 y = 2
i32 y = 9
echo(cstr(y))                // → 9
```

## Числа и приведение типов

### Расширение и сужение

Расширение типа (`i8` → `i32` → `i64`, целое → дробное, `float` → `f64`) происходит само. Всё, что может потерять данные, требует явного приведения `->`:

```ms
i32 big = 300
i64 wide = big               // ок
i8 small = big->i8           // ок: вы этого попросили
i8 oops = big                // ошибка: use explicit cast ->i8

f64 a = 0.5
float b = a                  // ошибка: use explicit cast
```

Литерал проверяется по значению: `i8 y = -128` можно, `i8 y = -129` — ошибка `does not fit`.

Приведение пишется сразу после значения и может стоять внутри выражения: `a + n->i64`, `(c->i32 + 1)->char`.

### Логические значения — это числа

`true` равно `1`, `false` равно `0`. Арифметика над `i1` даёт обычные числа:

```ms
x ^= 1
y ^= 1
echo("=" + (x + y))          // → =2
```

Приведение к `i1` — это проверка на ноль: `2->i1` и `-1->i1` дают `true`, `0->i1` — `false`. Условие `while 1` допустимо.

### Переполнение и деление

- `+`, `-`, `*` над целыми при переполнении заворачиваются: `2147483647 + 1` в `i32` даёт `-2147483648`.
- Деление на ноль останавливает программу: `division by zero at line N`.
- Деление самого маленького числа на `-1` тоже останавливает программу: `integer overflow`.
- Остаток от деления на `-1` всегда `0`. Знак остатка берётся от делимого: `-5 % 3 == -2`.
- Дробное деление на ноль даёт `inf`, `0.0 / 0.0` — `nan`.

### Приведение дробных к целым

Если значение не помещается в целевой тип, программа останавливается:

```ms
float a = 128.0
i8 x = a->i8                 // Runtime Error: float value out of range for i8 at line 4
```

Дробные числа печатаются в кратчайшей записи: `1.5`, `3.0`, `0.1`, `1.7e+09`.

## Строки и символы

### Строки

`string` — неизменяемая последовательность байт в UTF-8. Длина хранится вместе со строкой, поэтому `len(s)` и `s[i]` работают за постоянное время. Экранирование: `\n`, `\t`, `\r`, `\f`, `\b`, `\'`, `\"`, `\\`. Те же последовательности работают в литералах `char`, плюс `'\0'`.

Нулевого байта в строке быть не может: литерал `"a\0b"` — ошибка `Strings cannot contain a NUL byte`, а `cstr('\0')` останавливает программу.

```ms
string s = "abc"
echo(cstr(s[0]))             // → a
echo(cstr(len(s)))           // → 3
s[0] = 'x'                   // ошибка: Strings are immutable
```

- `s[i]` возвращает `char`. Индекс может быть любым целым типом. Выход за границы останавливает программу.
- Строки сравниваются операторами `==`, `!=`, `<`, `>`, `<=`, `>=`: `"abc" < "abd"`.
- Обход `for c in s` идёт по байтам, переменная цикла имеет тип `char`.

```ms
[string]rev(string: s)
|   string out = ""
|   i32 i = len(s) - 1
|   while i >= 0
|   |   out = out + s[i]
|   |   i = i - 1
|   return out
```

### Склейка

`+` склеивает строку с другой строкой, числом, `char` или `i1`:

```ms
i32 seen = 4
i1 done = true
echo("seen " + seen + ", done " + done)   // → seen 4, done true
```

Склеить строку с массивом, `map`, структурой или `result` нельзя: `Cannot join string with array<i32>`.

`cstr(x)` превращает в строку число, `char` или строку, по тем же правилам, что и склейка.

### Символы `char`

`char` — один байт. `'я'` в него не помещается: `A char is one byte`. Арифметики над `char` нет. Чтобы сдвинуть символ, его приводят к числу и обратно:

```ms
char c = 'a'
char d = (c->i32 + 1)->char  // 'b'
i32 digit = '3'->i32 - '0'->i32   // 3
char up = (c->i32 - 32)->char     // 'A'
```

Ограничения `char`:
- `char` сравнивается с `char` (`c < 'z'`), но не со строкой: `c == "a"` — ошибка.
- `char c = 65` — ошибка, нужно `65->char`.
- `i32 n = c` — ошибка, нужно `c->i32`.

## Операторы

| Оператор | Значение |
|---|---|
| `=` | Присваивание |
| `^=` | Объявление с выводом типа |
| `+ - * / %` | Арифметика, `+` также склеивает строки |
| `== != < > <= >=` | Сравнение чисел, `char` и строк |
| `and`, `or` | Логика. Правая часть вычисляется, только если нужна |
| `!` | Логическое НЕ |
| `->` | Приведение типа |
| `?r` | Есть ли значение в `result` (то же, что `r.ok`) |

Приоритет, от высокого к низкому:
1. `->` и унарные `!`, `-`, `?`;
2. `*` `/` `%`;
3. `+` `-`;
4. сравнения;
5. `and`;
6. `or`.

Операторы одного уровня левоассоциативны: `10 - 3 - 2 == 5`.

Массивы, `map`, структуры и `result` сравнивать нельзя.

## Условия и циклы

Скобки вокруг условия не нужны:

```ms
if x < lo
|   return lo
else if x > hi
|   return hi
else
|   return x
```

Условие должно быть числом или `i1`. `if c` для `char c` — ошибка `If condition must be ...`.

### Ветка в одну строку

После `:` можно написать одну простую инструкцию на той же строке. `else` и `else if` по-прежнему начинаются с новой строки, однострочные ветки и ветки-блоки можно смешивать:

```ms
[i32]sign(i32: n)
|   if n < 0: return -1
|   else if n == 0: return 0
|   else: return 1

[void]show(i32: n)
|   if n > 100
|   |   echo("big")
|   |   echo("very big")
|   else: echo("small")
```

- В ветке ровно одна инструкция: присваивание, вызов, `return`, `break`, `continue`, `const`, `final`. Вложенный `if` или цикл — ошибка `Inline if/else requires a single simple statement`, их пишут блоком.
- `if x:` без инструкции после двоеточия — ошибка `Expected a statement after ':'`.
- Форма с `:` есть только у `if` / `else`. `while x: ...` не разбирается.

### while

```ms
i32 i = 0
while i < 10
|   i = i + 1
|   if i % 2 == 0
|   |   continue
|   if i > 7
|   |   break
```

### for

| Форма | Переменная цикла |
|---|---|
| `for i in range(n)` | от `0` до `n - 1` |
| `for i in range(a, b)` | от `a` до `b - 1` |
| `for x in array` | элемент массива |
| `for key in map` | ключ, в порядке вставки |
| `for c in string` | байт строки, тип `char` |

```ms
array<i32> a = [10, 20, 30]
for i in range(1, len(a))
|   echo(cstr(a[i]))         // → 20, 30
```

Переменная цикла — копия элемента: запись в неё массив не меняет. Добавлять и удалять элементы в обходимой коллекции нельзя. Программа остановится с ошибкой `array changed during iteration` или `map changed during iteration`. Менять значения `map` по существующим ключам можно.

`range` работает только в заголовке `for`, его аргументы — целые числа.

## Функции

Тип возврата пишется в квадратных скобках, тип параметра — перед именем:

```ms
[i64]fibonacci(i64: n) @strict @pure
|   if n < 2
|   |   return n
|   return fibonacci(n - 1) + fibonacci(n - 2)
```

- Функцию можно вызвать до того, как она объявлена. Взаимная рекурсия тоже работает.
- Функция с типом возврата не `void` должна возвращать значение на каждом пути. Иначе ошибка `Function f must return`.
- В функции `void` можно написать `return` без значения, чтобы выйти раньше.
- Аргументы приводятся к типам параметров по обычным правилам: расширение само, сужение — ошибка.
- Две функции с одним именем — ошибка. Своя функция с именем встроенной (`copy`, `len`, `push`...) заменяет встроенную.

```ms
[i32]copy(i32: x)
|   return 42

echo(cstr(copy(1)))          // → 42
```

## Массивы

```ms
array<i32> scores = [10, 20, 30]
scores[0] = 5
push(scores, 40)             // добавить в конец
i32 last = pop(scores)       // снять последний
echo(cstr(len(scores)))      // → 3

array<array<i32>> grid = [[1, 2], [3, 4]]
grid[1][1] = 9
```

- Индекс — любое целое. Отрицательный индекс или выход за границы останавливает программу: `index 3 out of bounds (len 3)`.
- `pop` из пустого массива останавливает программу: `pop from an empty array`.
- Присваивание не копирует массив:

```ms
array<i32> a = [1]
array<i32> b = a
b[0] = 5
echo(cstr(a[0]))             // → 5
array<i32> c = copy(a)       // отдельная копия
```

Элементы литерала проверяются как присваивания: `array<i8> a = [300]` — ошибка.

## Словари map

```ms
map<string, i32> ports = {"ssh": 22}
ports["http"] = 80           // добавить или заменить
if has(ports, "ssh")
|   del(ports, "ssh")
for name in ports            // ключи в порядке вставки
|   echo(name + " = " + ports[name])
echo(cstr(len(ports)))
```

- Ключи — целые числа, `char` или строки. `float` и объекты ключами быть не могут.
- Строковые ключи сравниваются по содержимому.
- Чтение или `del` отсутствующего ключа останавливает программу: `key not found`.
- Повторяющийся ключ в литерале — ошибка компиляции `Duplicate key`.
- Значения могут быть любыми: `map<string, array<i32>>`, `map<string, map<string, i32>>`.
- Вложенная запись создаёт только последний ключ. `m["x"][0] = 1` при отсутствующем `"x"` — ошибка выполнения.

Пример из тестов компилятора: подсчёт тегов.

```ms
map<string, i32> tagCount = {}
array<string> tags = ["remote", "admin", "web", "admin"]
for t in tags
|   if has(tagCount, t)
|   |   tagCount[t] = tagCount[t] + 1
|   else
|   |   tagCount[t] = 1
for t in tagCount
|   echo("tag " + t + ": " + tagCount[t])
```

## Структуры и методы

```ms
[struct]User
|   i32 age = 18
|   string name = "anon"
|
|   [void]birthday()
|   |   self.age = self.age + 1
|
|   [string]describe() @pure
|   |   return self.name + " is " + self.age

[i32]main()
|   User user = User()
|   user.birthday()
|   echo(user.describe())    // → anon is 19
|   return 0
```

### Поля

- У каждого поля должно быть значение по умолчанию: `i32 age = 0`, `array<i32> v = []`. Без него ошибка `must have a default value`.
- Тип поля можно вывести: `f ^= 1`.
- Значение по умолчанию вычисляется заново при каждом создании объекта. Поэтому у каждого объекта свой массив или `map`:

```ms
i32 next = 0

[i32]nextId()
|   next = next + 1
|   return next

[struct]P
|   i32 id = nextId()

P a = P()                    // a.id == 1
P b = P()                    // b.id == 2
```

- Объект создаётся вызовом `Name()` без аргументов. Конструкторов с параметрами пока нет.
- Структура не может прямо или косвенно содержать саму себя: `N next = N()` внутри `N` — ошибка.
- Структуры вкладываются друг в друга, хранятся в массивах и `map`.

### Методы

- Методы объявляются внутри блока структуры. Объект внутри метода — `self`.
- К полям и другим методам обращаются только через `self.`: `return a` вместо `return self.a` — ошибка.
- `self` нельзя переприсвоить.
- Методы вызываются по цепочке вместе с полями и индексами: `o.inner.get()`, `o.me().v = 9`, `a[0].list()[1]`.
- `@pure`-метод не может менять `self`.
- У константы (`const P p`) можно вызывать только `@pure`-методы.
- Методы-шаблоны пока не поддерживаются.

Пример: структура, которую функция создаёт и возвращает.

```ms
[struct]Finding
|   string host = "?"
|   i32 port = 0
|   i32 score = 0
|   array<string> tags = []

[Finding]scan(string: host, i32: port)
|   Finding f = Finding()
|   f.host = host
|   f.port = port
|   if port == 22 or port == 3389
|   |   f.score = 90
|   |   f.tags = ["remote", "admin"]
|   return f
```

## Шаблоны функций

Параметры типа пишутся в `<...>` после имени. Типы выводятся из аргументов, явно `id<i32>(1)` их указать нельзя:

```ms
[T]first<T>(array<T>: items)
|   return items[0]

[array<T>]pair<T>(T: a, T: b)
|   return [a, b]

[V]get<K, V>(map<K, V>: m, K: k)
|   return m[k]

[i32]main()
|   echo(first(["a", "b"]))          // T = string → a
|   echo(cstr(first([1, 2])))        // T = i32 → 1
|   map<string, i32> m = {"a": 7}
|   echo(cstr(get(m, "a")))          // → 7
|   return 0
```

- Для каждого набора типов компилятор создаёт отдельную копию функции и проверяет её. Шаблон, который ни разу не вызван, не проверяется.
- Целый литерал без другого контекста становится `i32`: `id(1)` даёт `T = i32`. Рядом с аргументом настоящего типа литерал подстраивается под него: `big(w, 1)` при `i64 w` даёт `T = i64`.
- `T` может быть структурой. Тогда в теле доступны её поля и методы: `x.get()`.
- Ошибки компилятора:
  - `Cannot infer type T of f from its arguments` — например, `f([])`;
  - `T is both i32 and string` — аргументы противоречат друг другу;
  - шаблон не может быть точкой входа `@entry`.

## Функции как параметры

Функцию можно передать по имени в параметр `func`:

```ms
[array<T>]filter<T>(array<T>: items, func: keep(T: x) -> i1)
|   array<T> out = []
|   for x in items
|   |   if keep(x)
|   |   |   push(out, x)
|   return out

[i1]isEven(i32: x)
|   return x % 2 == 0

[i32]main()
|   array<i32> even = filter([1, 2, 3, 4], isEven)
|   return len(even)                 // 2
```

Сортировка по полю — пример из тестов компилятора:

```ms
[void]sortBy<T>(array<T>: items, func: less(T: a, T: b) -> i1)
|   for i in range(1, len(items))
|   |   i32 j = i
|   |   while j > 0 and less(items[j], items[j - 1])
|   |   |   T tmp = items[j]
|   |   |   items[j] = items[j - 1]
|   |   |   items[j - 1] = tmp
|   |   |   j = j - 1

[i1]byScore(Finding: a, Finding: b)
|   return a.score < b.score
```

- Передать можно и встроенную функцию: `via(toString_int, 7)`. И функцию без параметров: `func: f() -> i32`.
- Функцию можно только передать аргументом. Сохранить её в переменную (`g ^= id`), вернуть, положить в массив или участвовать с ней в арифметике нельзя.
- Сигнатура переданной функции должна точно совпадать с параметром.
- `@pure`-функция принимает только `@pure`-функции.

## Ошибки как значения: result

Функция, которая может не справиться, возвращает `result<T>`. Вызывающий проверяет результат, и программа продолжает работу:

```ms
[result<i32>]parseDigit(string: s)
|   if len(s) != 1
|   |   return err(1, "expected one digit, got " + s)
|   char c = s[0]
|   if c < '0' or c > '9'
|   |   return err(2, "not a digit: " + s)
|   return ok(c->i32 - '0'->i32)

[i32]main()
|   result<i32> r = parseDigit("x")
|   if ?r                            // то же, что r.ok
|   |   echo("digit " + r.value)
|   else
|   |   echo("error " + r.code + ": " + r.error)
|   return 0
```

| Поле | Тип | Значение |
|---|---|---|
| `r.ok` | `i1` | Есть ли значение |
| `r.value` | `T` | Значение. Чтение из ошибки — паника |
| `r.code` | `i32` | Код ошибки |
| `r.error` | `string` | Текст ошибки |

### Оператор `?`: передать ошибку наверх

Постфиксный `r?` разворачивает успешный результат. Если в `r` ошибка, функция сразу возвращает её с тем же кодом и текстом:

```ms
[result<i32>]sumNumbers(string: a, string: b)
|   i32 x = toInt(a)?
|   i32 y = toInt(b)?
|   return ok(x + y)

[i32]main()
|   r ^= sumNumbers("2", "x")
|   if !r.ok: echo(cstr(r.code) + " " + r.error)   // → 1 expected a decimal integer
|   return 0
```

- Без обработчика `?` можно писать только в функции, которая сама возвращает `result<U>`. `U` может отличаться от развёрнутого типа. В `main` без обработчика это ошибка `Postfix '?' requires a function returning result<T>`; обработать ошибку на месте помогают [`attempt` и `? else`](#обработка-на-месте-attempt-и--else).
- Префиксный `?r` остался проверкой успеха (`i1`), постфиксный `r?` — разворачивание.
- Выражение слева вычисляется один раз. `?` связывается раньше арифметики: `toInt(s)? * 2`.
- Каст после разворачивания: `toInt(s)?->i64`. Вложенный результат разворачивается двумя знаками: `r??`.
- Для `result<void>` — отдельной инструкцией: `save(path)?`.

То же вручную, без `?`:

```ms
[result<i32>]twoDigits(string: a, string: b)
|   result<i32> x = parseDigit(a)
|   if !x.ok: return err(x.code, x.error)
|   result<i32> y = parseDigit(b)
|   if !y.ok: return y
|   return ok(x.value * 10 + y.value)
```

Правила:
- **Результат нужно использовать.** Вызов `act()` без чтения результата — ошибка `The result is not used`. Чтобы проигнорировать результат намеренно, пишут `_ ^= act()`.
- **Значения может не быть:** `result<void>` и `return ok()`. Код ошибки можно опустить: `err("disk full")`.
- **Тип `ok()` и `err()` берётся из места назначения.** Поэтому `r ^= ok(1)` — ошибка `Cannot infer the type of ok()`.
- **Значение в `ok()` приводится к `T` по обычным правилам:** `ok(x)` с `i32 x` подходит для `result<i64>`.
- **Поля `result` только для чтения.** `result` нельзя сравнивать и склеивать со строкой.
- **`result` хранится в массивах и `map`, передаётся в функции и возвращается из методов:** `array<result<i32>>`, `map<string, result<i32>>`.
- **Забытая проверка — паника с исходной причиной:** `result has no value: not a digit: z at line 13`. Её ловит `panic info`, иначе программа завершается с кодом `101`.

### Обработка на месте: `attempt` и `? else`

Ошибку можно обработать прямо там, где она случилась, — в том числе в обычной функции вроде `[i32]main()`:

```ms
[i32]main()
|   port ^= toInt("invalid")? else 8080
|   n ^= toInt("42")? else: echo(error.error); return error.code
|
|   attempt
|   |   value ^= toInt("7")?
|   |   array<i32> rows = [value]
|   |   echo("" + rows[9])
|   else error
|   |   echo(error.error)
|   panic info
|   |   echo(info.message + " at line " + info.line)
|   return 0
```

**`r? else значение`** — замена при ошибке. Результат вычисляется один раз, замена — только при ошибке. Она должна подходить к развёрнутому типу (`toInt(s)? else "bad"` — ошибка `Fallback: Type mismatch`). Замены можно цеплять: `a()? else b()? else 3`. Внутри большего выражения замену берут в скобки: `"" + (r? else 'B')`. У `result<void>` замены нет. Работает и для глобальных переменных: `i32 port = toInt(s)? else 8080`.

**`r? else: инструкции`** — действие при ошибке в одну строку. Инструкции разделяются `;`, последняя — обязательно `return`, `break` или `continue`. Внутри доступна `error` (`result<void>`, только для чтения: `.ok`, `.code`, `.error`), снаружи её нет. Действие забирает остаток строки, поэтому пишется в конце инструкции:

```ms
for s in inputs
|   n ^= toInt(s)? else: echo("skip"); continue
|   echo("" + n)
```

**`attempt`** — блок с обработчиками на том же уровне:
- `else error` — ошибки голого `?` внутри блока в **этой же функции**. Вызванные функции по-прежнему возвращают ошибки через свой `result`.
- `panic info` — паники, в том числе из глубины вызовов: деление на ноль и переполнение, неверные приведения, выход за границы массива или строки, `pop` из пустого массива, нет ключа `map`, изменение `map` при обходе, чтение `.value` из ошибки, ошибки строковых функций стандартной библиотеки. `info` — снимок `panic_info` с полями `.message` и `.line` (`0`, если строка неизвестна), только для чтения.

Правила:
- Нужен хотя бы один обработчик, каждый — не больше одного раза (`Duplicate else handler`).
- Переменные тела не видны в обработчиках и после `attempt`.
- Когда обработчик закончился, выполнение продолжается после всего `attempt`. Внутри обработчиков можно `return`, `break`, `continue`.
- Ошибка внутри обработчика уходит во внешний `attempt`, а не в соседний обработчик того же блока.
- `? else` обрабатывает только ошибки `result`: паника при вычислении операнда или замены идёт в окружающий `panic info`.
- Побочные эффекты не откатываются. Нехватка памяти и падения нативного кода по-прежнему завершают программу. `defer` и автоматической очистки ресурсов пока нет.
- `final` переменная, которой присвоено значение в теле `attempt`, считается присвоенной после него, только если каждый обработчик выходит из функции.

## Метки

Метки пишутся после списка параметров, их можно сочетать: `[i64]f(i64: n) @strict @pure`.

| Метка | Действие |
|---|---|
| `@entry` | Точка входа вместо `main` |
| `@strict` | Строгие типы в этой функции |
| `@pure` | Без побочных эффектов, проверяется компилятором |
| `@private` | Функция не видна при импорте модуля |
| `@overwrite` | Намеренно заменяет импортированную функцию с тем же именем |

### @strict

В функции с `@strict`:
- нет неявного расширения: `float f = a` при `i32 a` — ошибка;
- нельзя смешивать числовые типы в одной операции: `a + n` при `i64 a` и `i32 n` — ошибка `Implicit cast is not allowed in @strict mode: i64 and i32`;
- результат сравнения нельзя присвоить числу без каста.

Литералы подстраиваются под тип, если значение помещается:

```ms
[i64]f(i64: a, i32: n) @strict
|   i64 x = a + 1                // ок: литерал
|   i64 z = a + n->i64           // ок: явный каст
|   return x + z

[f64]g(f64: d) @strict
|   return d + 0.5
```

### @pure

Чистая функция не меняет ничего за своими пределами. Компилятор проверяет, что она:
- не вызывает нечистые функции (например, `echo`);
- не читает и не пишет глобальные переменные;
- не меняет переданные ей объекты, в том числе через новую ссылку на них (`P q = x`);
- не возвращает переданный объект и не кладёт его в другой объект или `result`: `return a` для `array<i32>: a` — ошибка;
- не копирует объект, если копия делит с аргументом вложенные изменяемые объекты: `copy(a)` для `array<array<i32>>` — ошибка, потому что `copy` отделяет только внешний массив;
- принимает в `func`-параметрах только `@pure`-функции.

Последние две проверки осторожные: компилятор может отклонить и безопасный код. Сообщение в обоих случаях — `Pure function cannot create a new reference to object passed to it`.

Свои локальные объекты и копии менять можно:

```ms
[i32]f(P: x) @pure
|   P q = copy(x)
|   q.age = 5                    // ок: это копия
|   return q.age

[void]g(array<i32>: x) @pure
|   x[0] = 7                     // ошибка: cannot modify object
```

Встроенные функции для строк, а также `len`, `has`, `copy`, `cstr` — чистые. `echo`, `input`, `push` и `del` для чужих объектов — нет.

## Модули

```ms
use
|> http_server               // весь модуль
|> math -> sqrt              // одна функция
|> math -> pow : power       // функция под другим именем
```

- Модуль — это файл `имя.ms`. Компилятор ищет его сначала в стандартной библиотеке (`mono/`), потом рядом с импортирующим файлом.
- Импорт одной функции скрывает остальные функции модуля.
- Функции с `@private` видны только внутри своего модуля.
- Структуры и шаблоны из модулей тоже импортируются.

Своя функция с тем же именем, что и импортированная, — ошибка `conflicts`. Её можно разрешить двумя способами:

```ms
use
|> lib2

[i32]helper() @overwrite     // 1) намеренная замена
|   return 100
```

```ms
use
|> runlib -> helper : lh     // 2) импорт под другим именем

[i32]helper()
|   return 100
```

## Ошибки во время выполнения

Это паники: их ловит обработчик `panic info` блока `attempt`, в том числе из вызванных функций (см. [обработку на месте](#обработка-на-месте-attempt-и--else)). Без обработчика программа останавливается с сообщением, номером строки и кодом выхода `101`:

```
Runtime Error: index 3 out of bounds (len 3) at line 5
```

| Сообщение | Причина |
|---|---|
| `index N out of bounds (len M)` | Индекс массива или строки за границами |
| `key not found` | Чтение или `del` отсутствующего ключа `map` |
| `division by zero` | Целое деление или остаток на ноль |
| `integer overflow` | Деление самого маленького числа на `-1` |
| `float value out of range for i8` | Приведение дробного, которое не помещается |
| `pop from an empty array` | `pop` из пустого массива |
| `array changed during iteration`, `map changed during iteration` | `push`, `pop` или `del` во время обхода |
| `result has no value: ...` | Чтение `value` из ошибки |
| `substr: range is outside the string`, `split: empty delimiter` | Неверные аргументы строковых функций |
| `strings cannot contain a NUL byte` | `cstr('\0')` или `toString_char('\0')` |

## Нативные функции на D

Стандартная библиотека написана на D. Новая нативная функция — это `extern(C)` функция в `mono/std/...` и одна запись в `mono/mono.toml`:

```toml
[[function]]
name = "strfind"
pure = true
ret = "i32"
args = ["string", "string"]
```

Функция, которая возвращает `result<T>`, собирает его через `resultOk`, `resultErr`, `resultVoidOk` и `resultVoidErr` из `mono/std/core/abi.d`.

Чтобы паники нативной функции ловил `panic info`, в записи ставят `panic_context = true`. Тогда функция получает последним аргументом `MsPanicContext*` (после аргументов из `args`), сообщает об ошибке через `ms_raise(message, line, context)` и **сразу возвращается**. Ошибки своих помощников она тоже передаёт дальше, прежде чем использовать их результат. Функция без этого флага остаётся обычным вызовом C, а `ms_panic` по-прежнему завершает программу. После этого изменения соглашения о вызовах программы и нативные библиотеки нужно пересобрать.

Строки передаются как указатель на данные, совместимый с C, но прямо перед данными лежит длина (`u64`). Поэтому строку, которую функция возвращает, создают только через `newString(length)`, `stringFromBytes(data, length)` или `stringFromCString(text)` из того же модуля. Литерал C/D или буфер из `malloc` возвращать нельзя. `resultErr` сам копирует текст ошибки в этот формат. После обновления рантайма нативные расширения и программы нужно пересобрать.

- лямбды `[i32](i32: a) -> a + 1`;
- пайпы `|>` внутри выражений (в `use` они работают);
- оператор `**`;
- null safety и встраивание в другие программы — в планах.
